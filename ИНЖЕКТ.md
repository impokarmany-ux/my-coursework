# ИНЖЕКТ — бот, который шлёт команды через живую игру

## 1. Откуда на самом деле выходил трафик (проверено 31.10, 15:58 по Киеву)

В netbot_test (emulator-5560) Surfshark работает как VpnService: интерфейс `tun1` (10.14.0.2).
Но в его маршрутах **172.16.1.0/24 (локальная сеть LDPlayer) исключена из VPN**:

```
ip route get 172.16.1.2  -> dev wlan0   (мимо VPN)
ip route get 8.8.8.8     -> dev tun1    (через VPN)
```

- `curl ipinfo.io` прямо из Android -> **203.0.113.20, Стамбул, Datacamp** (Surfshark).
- Ноутбук -> **203.0.113.10, Варна, Geodim** (дом).

Когда в эмуляторе стоит `http_proxy 172.16.1.2:8080`, игра отдаёт запрос прокси на ноутбуке
по wlan0 (мимо VPN), а mitmdump сам выходит в интернет **с домашнего IP**.
**Значит, все сегодняшние MITM-записи (полный круг, страж, 3 круга) и все команды
скриптов 10/11 шли с 203.0.113.10.** Без прокси игра ходит через Surfshark.

## 2. Как заставить выход идти через VPN окна (выбран вариант A)

```
игра -> http_proxy 172.16.1.2:8080 -> mitmdump + inject.py (ноутбук)
     -> upstream 127.0.0.1:18081 -> adb forward -> vpnproxy (внутри Android) -> tun1 Surfshark -> сервер
```

- `mitm\tools\vpnproxy.bin` — наш крошечный HTTP/CONNECT-прокси (исходник `vpnproxy.go`, ~60 строк Go).
  Запускается в Android от пользователя shell, а правило `uidrange 0-99999 lookup tun1` отправляет его трафик в VPN.
  DNS спрашивает у 1.1.1.1 тоже через VPN.
- Проверка: `curl -x http://127.0.0.1:18081 https://ipinfo.io/json` с ноутбука -> **203.0.113.20 (Surfshark)**. Работает.
- Готовый gost Windows Defender удалил как «хак-тулзу», поэтому написал свой прокси.
- mitmdump запускается с `--mode upstream:http://127.0.0.1:18081`: и игра, и наши команды выходят через VPN.
- Если Surfshark отвалится, Android пустит трафик через wlan0, то есть с домашнего IP. Поэтому START_INJECT.ps1 и inject.py
  перед отправкой проверяют внешний IP и не шлют, если он 203.0.113.10.

## 3. Как вставляем команды, не ломая игру

Где живёт seq (проверено по записи стража):
- **запрос**: только поле верхнего уровня `"seq"` в `{"class":"call","method":"commit",...}`;
- **ответ**: обычный ответ commit seq **не содержит** (`{"payload":..,"data":..,"time":..,"ok":1}`);
  seq есть только в `{"ok":98,"seq":N}`, когда сервер ждёт другой номер.

Алгоритм inject.py:
1. AES-ключ берётся из `ak` в открытом ответе versionDiff2 (игру надо запустить уже под прокси).
   Если игра была запущена раньше, ключ подбирается из `mitm\session_*.json`.
2. С каждого call:commit игры запоминаем session_key, token, fpid, uid, cv/bvr/bvg и `last_seq`.
3. Наша команда: `seq = last_seq + 1`, отправка через vpnproxy, потом `offset += 1`
   (ошибка тоже сжигает seq, поэтому offset растёт при любом ответе, кроме ok:98).
4. Все следующие commit игры: `seq_на_сервер = seq_игры + offset` (расшифровка -> правка -> шифрование).
5. Ответ ok:98 игре: `seq_игре = seq_сервера - offset`, и last_seq обновляется.
6. Одна запись в полёте: пока commit игры ждёт ответа, наша команда ждёт, и наоборот (asyncio.Lock).
7. Ответ на нашу команду игре не показывается, поэтому город на экране обновится только после перезахода.

Защиты: пробный режим по умолчанию (`inject_live=false`), список разрешённых op, gold всегда 0,
uid в команде должен совпасть с uid живой сессии, проверка VPN-IP.

## 4. Файлы

| файл | что |
|---|---|
| `mitm\inject.py` | аддон mitmdump |
| `13_inject_cmd.py` | кладёт команду в `mitm\inject_inbox\`, ждёт ответ из `inject_outbox\` |
| `mitm\START_INJECT.ps1` [-Live] / `STOP_INJECT.ps1` | запуск/остановка всей цепочки |
| `mitm\tools\vpnproxy.bin`, `vpnproxy.go` | прокси внутри Android |
| `logs\inject_*.log` | лог: каждый seq игры и наш |
